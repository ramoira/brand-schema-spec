# Migrating from 3.0.0 to 3.1.0

3.1.0 adds optional fields to `draft_provenance`, the record of how a candidate was drafted. Nothing inside `content_hash` changes, so **no schema needs re-ratifying** and every `ratified_hash` still matches.

## Do I need to change anything?

No. A 3.0.0 document stays valid under the 3.1.0 validator, as long as it keeps `"spec_version": "3.0.0"`.

Change `spec_version` to `"3.1.0"` only when you want the new fields. A document that declares 3.0.0 and carries one of them is refused, so a consumer that only understands 3.0.0 is never handed a document it cannot read.

## Moving a document to 3.1.0

1. Set `ramoira.spec_version` to `"3.1.0"`. The `content_hash` does not change.
2. If the document has `draft_provenance.closeness_ratings`, give each rating an `answered_by`: the `participant_id` of whoever rated (required in 3.1.0). If you do not know who rated, keep the document at 3.0.0.
3. Optionally add the new fields below.

## What is new

| Field | What it records |
|---|---|
| `closeness_ratings[].answered_by` | Who rated. Required in 3.1.0. |
| `closeness_ratings[].basis` | `intended` (how close the brand should be; the default when absent) or `current` (how its content sounds today) |
| `closeness_ratings[].exemplars_known` | `false` when the participant does not know the exemplar brands; `closeness` is then `null` |
| `contrast_sets[]` | For one delta zone: the probe lines shown, the one most like the brand (`best`), least like it (`worst`), or `none_of_these`, and the participant's reason |
| `reactions[].set_id` | Links a reaction to its contrast set. The best probe is recorded as `yes`, the worst as `no`. |
| `retests[]` | A contrast set shown again to the same participant |
| `competitor_ratings[]` | A participant's placement of a named competitor on the archetypes: a perception the brand records, never a measure of the competitor |

None of these is a result. How often retests agree, or how well an anchor fits the choices made, is computed by whoever reads the record and is never stored in the schema (SPEC.md section 1).

## Validation

Invariant 12 checks that the record is consistent: unknown exemplars mean a null closeness; no duplicate ratings; choices are among the set's probes; `none_of_these` holds exactly when there is no best probe; the chosen probes appear as reactions; a retest is answered by the same participant as its set. See SPEC.md section 12.
