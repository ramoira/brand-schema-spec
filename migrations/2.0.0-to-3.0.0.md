# Migrating from 2.0.0 to 3.0.0

3.0.0 is one breaking release. It changes three things about what a schema *is*:

1. **A schema carries meaning, never results.** `certified`, `confidence` and the `certified` workflow state are gone, with no replacement number. Results about content live in the verification record (`record.schema.json`), never in the schema.
2. **Every rule lives once, in a registry.** v2 spread prohibitions across a dozen lists and kept severity in free strings, so a finding could not cite a rule. In v3 each prohibition or requirement is a rule object with a `rule_id`, a `check_class` and a `severity`. Layers keep facts and density only.
3. **A schema is version-bound by its content.** `content_hash` (SHA-256 over the canonical JSON of the rules and five layers) is the version. `schema_version` is a label.

Nothing about the summary depends on pricing any more: rejected examples, context variants, rails, myth evolution and pillars are includable at every tier, identically.

There is no automatic converter. Turning a forbidden-word list into rules is mechanical; deciding which forbidden *meanings* can be checked, and with which examples, is the brand's judgment. Work through the steps below, then run the validator.

---

## Step 1 — Top level and metadata

v2 had `meta` plus `_component` / `_version` on each layer, and a separate `ramoira` metadata block. v3 has one `ramoira` block and no per-component versions.

| v2 | v3 |
|---|---|
| `meta.brandId` | `ramoira.brand_id` |
| `meta.brandName` | `draft_provenance.intake.name` (the brand's name is not brand *meaning*; put it in copy rules if it must be checked) |
| `meta.schemaVersion` | `ramoira.schema_version` (a label only) |
| `meta.effectiveDate`, `previousVersion`, `changelog` | Removed. History is the sequence of `content_hash`es. Keep a changelog beside the file if you want one. |
| `ramoira.spec_version` | `"3.0.0"` |
| `ramoira.schema_type` | `full`, `summary` or `archetype` |
| `ramoira.workflow_state` | Unchanged values: `draft`, `in_review`, `published`, `archived`. There is no `certified` state. |
| `ramoira.certified` | **Removed** |
| `ramoira.confidence` | **Removed** |
| `ramoira.schema_contract_version` | **Removed** (one version axis: `spec_version`) |
| `ramoira.owner_verified` | `ramoira.account_owner_verified` (slug ownership; never ratification) |
| `ramoira.canonical_url` | Unchanged |
| — | `ramoira.content_hash` (new, required) |
| — | `ramoira.ratification` (new; `null` until the brand ratifies) |
| — | `ramoira.summary_opt_in` (new, optional in a full schema) |
| `<layer>._component`, `<layer>._version` | **Removed** |

## Step 2 — Move every prohibition into `rules`

Each source below becomes one or more rule objects (see `SPEC.md` section 6). Choose `check_class` by what can actually be checked:

- a named word, phrase, competitor or colour → `deterministic_exact` with `match.terms`;
- a measurable or structural condition (a number, a required phrase, a claim that must be approved, a pronoun) → `deterministic_structural` with a `predicate`;
- anything that needs judgment → `judged_bounded`, **only** if you can cite at least one approved and one rejected example the brand judged, or a rail with both an example and an anti-example. If you cannot, move it to `narrative.guidance` as a question; it will not produce verdicts until it has examples.

| v2 location | v3 rules |
|---|---|
| `identity.distinctiveAssets.linguistic.forbiddenWords[]` (`Constrained`) | `deterministic_exact`; `severity` from the `Constrained` value |
| `identity.distinctiveAssets.linguistic.ownedPhrases[]` (`Constrained`) | The phrases stay as plain strings in `ownedPhrases`; misquoting becomes `deterministic_exact` rules on the altered forms, with the old severity |
| `identity.distinctiveAssets.linguistic.typographicVoice` | Keep the description; add `deterministic_structural` rules for checkable parts (punctuation, numerals) |
| `identity.distinctiveAssets.visual.forbiddenColors`, `logoUsage.forbiddenBackgrounds`, `logoUsage.forbiddenModifications`, `photographyStyle.forbidden` | Rules with `modality: visual` |
| `identity.distinctiveAssets.sonic.forbiddenGenres`, `tempoRange` | Rules with `modality: audio` (`tempoRange` → predicate `tempo_range`) |
| `identity.prism.relationship.pronoun` | `deterministic_structural`, predicate `self_reference_form` |
| `identity.prism.physique.forbidden`, `culture.forbidden`, `reflection.forbiddenArchetypes`, `selfImage.forbidden` | `judged_bounded` rules (need rubric examples) |
| `identity.summary.neverDo[]` | Each item becomes a rule of its own class |
| `narrative.semiotic.denotative.forbiddenClaims` and `commercial.claims.forbidden` | One set of `deterministic_exact` or `deterministic_structural` rules |
| `narrative.semiotic.connotative.forbiddenMeanings` | `judged_bounded` rules |
| `narrative.myth.constraints[]` | `judged_bounded` rules, with the constraint's severity and rationale. Its `example` ("VIOLATION: … — COMPLIANT: …") becomes a rejected and an approved example in `voice.examples`. |
| `narrative.mythEvolution.modernTensions[].forbiddenFraming`, `pillars[].forbiddenInversions`, `editorial.forbiddenStructures` | `judged_bounded` rules |
| `narrative.editorial.forbiddenReferences` | `deterministic_exact` where the reference is named; otherwise `judged_bounded` |
| `narrative.contentTest.*`, `myth.mythTest`, `connotative.minimumConnotativeTest`, `governance.preflight.*` | `judged_bounded` rules with `rubric.question` if examples exist; otherwise `narrative.guidance` |
| `voice.base.forbiddenDevices`, `voice.base.structuralRules`, `voice.forbiddenTones` | Rules of the fitting class |
| `voice.base.sentenceLength` | `deterministic_structural`, predicate `max_sentence_words` (per-surface `sentenceLength` stays in `contextVariants`) |
| `voice.contextVariants[].additionalForbidden` | Rules with `surfaces: [that surface]` |
| `commercial.pricing.priceDisplayPermitted / discountPermitted / urgencyLanguagePermitted / scarcityLanguagePermitted: false`, `maxDiscountPercent`, `forbiddenLanguage` | `deterministic_structural` and `deterministic_exact` rules (e.g. `max_number {field: "discount_percent", max: 15}`) |
| `commercial.claims.comparative.*`, `superlatives.forbidden`, `superlatives.permitted: false` | `deterministic_exact` rules (competitor names, phrases) plus structural rules for comparative framing |
| `commercial.offers.forbiddenTypes`, `communicationRules.urgencyPermitted / scarcityPermitted: false` | Rules |
| `commercial.socialProof.*Permitted: false`, `forbiddenSocialProof` | Rules |
| `commercial.globalForbiddenTerms`, `governance.compliance.zeroToleranceTerms` | `deterministic_exact` rules; zero-tolerance items get `severity: absolute` |
| `governance.severity.{absolute, strong, contextual}.constraints[]` | Each string becomes a rule; the bucket becomes its `severity`. `violationResponse` is not stored: it follows from severity. |
| `governance.compliance.geographicOverrides[]` | Rules with `markets` |

For every rule set:

- `topic`: a dot path such as `commercial.pricing.urgency`;
- `surfaces: "all"`, `markets: "all"`, `situations: "any"`, `modality: "text"` unless the rule is narrower;
- `visibility`: `private` for `commercial.*` and `governance.*` topics, `public` otherwise, unless you decide differently;
- `provenance: "authored"`, `affirmed: true` for rules the brand wrote.

Duplicates across v2 lists (the same term in `forbiddenWords`, `forbiddenClaims` and `zeroToleranceTerms`) become **one** rule.

## Step 3 — Reshape the layers

### Identity

| v2 | v3 |
|---|---|
| `prism.personality.{sincerity, excitement, competence, sophistication, ruggedness}` | **Removed** from brand schemas. Keep `characterBrief`. |
| `prism.relationship.mode` | **Removed** from brand meaning. If the schema was drafted from an archetype, record it in `draft_provenance.anchors`. |
| `prism.relationship.powerDynamic` | **Removed** |
| `prism.relationship.formality`, `warmth` | Unchanged values; now on the shared anchored scales (`SPEC.md` 8.6). Integers 0–10. |
| `prism.reflection.depictedArchetype` | Renamed `depictedCustomer` |
| `prism.reflection.aspirationalDelta` | **Removed** |
| `distinctiveAssets.visual.primaryColor` (`{value, severity}`) | A plain hex string |
| `identity.summary` | **Removed** from the schema. Derive a brief on export if you need one; its `neverDo` items became rules in step 2. |

### Narrative

| v2 | v3 |
|---|---|
| `semiotic.denotative.functionalClaims[]` and `commercial.claims.approved[]` | One list: `semiotic.denotative.claims[]`, each `{claim_id, claim, evidenceRequired, evidenceType, markets, surfaces}`. `geographicScope` → `markets`. |
| `semiotic.layerHierarchy` | **Removed** (say it in `editorial.structuralApproach` if it matters) |
| `myth.mythTest`, `contentTest`, `connotative.minimumConnotativeTest` | Rules or `guidance` (step 2) |
| `mythEvolution`, `pillars`, `editorial` | Unchanged apart from the forbidden lists (step 2) and rail ids (below) |
| — | `guidance[]` (new): `{question, applies_to}` |

### Voice

| v2 | v3 |
|---|---|
| `base.humourPermitted` + `base.humourStyle` | `base.humourStyle: {style, frequency?}`; `style: "none"` replaces `humourPermitted: false` |
| `base.sentenceLength`, `forbiddenDevices`, `structuralRules` | Rules (step 2) |
| `base.vocabularyLevel` | Unchanged; integer 0–10 on the shared scale |
| `forbiddenTones` | Rules (step 2) |
| `examples[]` `{context, text, verdict, reason}` | `{example_id, surface, text, verdict, reason, judged_by, source, captured_at?}`. `context` → `surface`. Set `judged_by` truthfully: who actually judged the example. Only `brand_owner` and `brand_team` examples can ground a verdict once the schema is ratified. |
| Every `Rail` | Add a `rail_id`, unique across the schema |

### Commercial

| v2 | v3 |
|---|---|
| `pricing.style` (enum) | Open-vocabulary string; same values still work |
| `pricing.*Permitted`, `maxDiscountPercent`, `forbiddenLanguage` | Rules |
| `claims.approved` | Moved to `narrative.semiotic.denotative.claims` |
| `claims.superlatives.approved` | Unchanged |
| `surfaceRules` | Moved to `governance.surfaces` |
| `globalForbiddenTerms` | Rules |

### Governance

| v2 | v3 |
|---|---|
| `severity` | **Removed**; each constraint is a rule with its own severity |
| `severity.strong.overrideProcess`, `severity.contextual.judgmentBounds`, `overrideProtocol.{authorisedRoles, requiredFields, maxDurationDays}` | One `override` object |
| `overrideProtocol.auditLogEndpoint`, `compliance.violationWebhook`, `compliance.routing` | **Removed**: integration configuration, not brand meaning |
| `surfaceRules[]` (governance) + `commercial.surfaceRules[]` | One `surfaces[]` list. `applicableConstraints` is replaced by each rule's `surfaces`; `suspendedConstraints` → `suspended_rule_ids` (contextual rules only); `primaryRail` → a `rail_id`. |
| `compliance.humanReviewTopics` | `reviewTopics` |
| `preflight.question1–3` | Rules or `narrative.guidance` |
| `contextVariants` or `surfaceRules` entries keyed by made-up surfaces (`competitive`, `crisis_response`, `social`, `press`, `retail`) | `situations[]` (new). These were circumstances, not surfaces. See below. |

**Situations.** If v2 used a surface name that is not an `OutputSurface` to describe a circumstance ("competitive", "crisis_response"), make it a situation: `{situation_id, trigger, category, posture, surfaces, voice, rails, suspended_rule_ids}`. Rules that apply only in that circumstance get `situations: ["sit_…"]`.

## Step 4 — Summary

The v2 summary withheld rejected examples, context variants, rails, myth evolution and pillars as "Studio tier value". In v3 the summary includes all of identity, narrative and voice, and every public rule. It excludes by default only the `commercial` and `governance` layers, private rules and `sacredBoundary`; the brand opts any of these in through `ramoira.summary_opt_in`, identically at every tier.

Do not hand-edit summaries. Generate one:

```bash
npm run summarize -- brand.schema.json brand.schema.summary.json
```

## Step 5 — Hash and validate

```bash
npm run hash -- brand.schema.json --write
npm run validate -- brand.schema.json brand.schema.summary.json
```

The validator names the invariant behind each error (`SPEC.md` section 12).

## Step 6 — Leave it unratified

A migrated schema is a candidate: `ratification: null`. Migration changes the shape, and judgment calls you made while migrating (which forbidden meanings became which rules, which examples ground them) are exactly what the brand ratifies. If the v2 schema was drafted by a tool or a producer, mark inherited rules `provenance: "inherited", affirmed: false` and examples with the role that actually judged them, so the brand can see what it has not yet affirmed.

## Checklist

- [ ] No `meta`, `_component`, `_version`, `certified`, `confidence`, `schema_contract_version`
- [ ] Every v2 forbidden list, `*Permitted: false` flag and severity string is a rule, or a `guidance` question
- [ ] Every `judged_bounded` rule cites an approved and a rejected example, or a rail with both
- [ ] Every rail has a `rail_id`; every example an `example_id`, `judged_by` and `source`
- [ ] One approved-claims list, in `narrative.semiotic.denotative.claims`
- [ ] Made-up surfaces turned into situations
- [ ] No webhooks or routing in the schema
- [ ] `content_hash` written; `ratification: null`
- [ ] Summary regenerated; validator passes
